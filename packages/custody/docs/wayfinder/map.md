# CUSTODY — wayfinder map

## Destination

A **decision-complete build plan** plus a **working vertical slice**, such that a builder can spend
the remaining hours implementing without making another architectural decision — and the slice
proves the airlock changes outcomes under concurrent, conflicting intents.

Operationally: the plan is done when no design question blocks the build; the slice is done when
`bun run custody` shows a live multi-agent run (not the fixture) and the ablation reports
`naive > 0` harmful actions and `custody = 0`, with the patched-replay arm available wherever the
baro handoff permits it.

**Status:** all tickets closed 2026-10-30. The frontier is empty; the map is done. Execution follows
the [Vertical slice contract](tickets/C15-vertical-slice-contract.md).

## Notes

- **Track:** Freestyle. One entry per team; the entry can change until **Sat 31 Oct 14:00 CET**.
- **Constraints:** must use Mozaik and run two or more concurrent agents; no production mutation;
  the demo must work **offline**; one builder, roughly 14 usable hours.
- **North star (not this map):** an authority layer for any agent that can touch production —
  capability-scoped, evidence-locked, auditable — demonstrated by closing one loop from attack to
  merged fix to a replay that no longer works. Do not ticket the whole platform; the map stops at
  the plan and the slice.
- **Dual-build constraint:** the scenario runner must execute one scenario against both the
  vulnerable and the patched build. Without that, the closed loop is unprovable after the fact.
- **Integration seam:** baro takes a *goal file*, not an issue URL, and is invoked as a subprocess.
  The handoff contract is the goal and the PR — never baro's internals.
- **Existing state:** the pure airlock, invariants, registry, state, events, session, money scenario
  and replay exist; 18 tests pass; the interception adapter is typed but unwired. The worker/pool,
  trace observer, adapters, viewer, scenario suite, ablation harness and baro handoff do not exist.
- **Standing preference:** decisions, not deliverables. Only the `prototype` tickets produce
  artifacts. Everything else is a decision that unblocks a builder.
- **Skills:** `grilling` and `domain-modeling` for every grilling ticket; `prototype` for any
  UI/UX ticket; `research` for the adapter and API-fact tickets.
- **Claim discipline:** no ablation or Docker number is claimed until it is generated by a committed
  artifact and reproducible by a command. "No numbers yet" is a valid README state.
- **Fallback:** EUREKA to Track 02 if the 22:00 Fri go/no-go fails. Do not let this map become a
  reason to miss the deadline.
- **Tracker:** local markdown in this directory. See `README.md` for the frontmatter, the claim
  convention, and the frontier query. Refer to tickets by name, never by bare id.

## Decisions so far

- [Correlation mechanics in Mozaik v4.1.0](tickets/C01-correlation-mechanics.md) — `handle()` can await a peer and rewrite a held `function_call`; no identity on the transition, no timeout/lock, `pause`/`stop` unreachable, no completion event. [findings](../research/c01-correlation-mechanics.md)
- [Docker adapter reversibility and evidence capture](tickets/C02-docker-reversibility.md) — nginx `deny` is ingress, not egress; pause/unpause, block/unblock, drain/re-add and scale-back are reversible if prior state is recorded; revoke has no undo; a two-container stack suffices. [findings](../research/c02-docker-reversibility.md)
- [Live correlation mechanism](tickets/C03-live-correlation.md) — the handler suspends and publishes `intent.proposed`; a dedicated Airlock participant owns a per-incident 1500 ms window, reconciles by arrival order, resolves each handler, and executes accepted retries through the shared executor port; timeout fails closed.
- [Authority precedence](tickets/C04-authority-precedence.md) — fixed evidence-first order; evidence defers only destructive actions; all findings recorded; no policy switch.

## Not yet specified

<!-- In-scope fog: questions that are not sharp enough to ticket yet. Graduates as the frontier advances. -->

- **Red-team generator:** an agent that mutates scenarios to find invariant violations in the
  `custody` arm. Depends on the ablation and the live run existing first; not in the first ablation.
- **Multi-tenant / network integration:** what "on top of existing infrastructure" means beyond one
  local Compose stack. Depends on the adapter-scope decision; the slice is Docker + sim only.
- **Persistence and replay:** whether a run can be resumed from a trace. Not needed for the demo;
  process death has no recovery in the slice, and the story may want it.
- **Live-mode cost and latency budget:** a real-provider run with token cost, latency and a clean
  fallback. The mock is free and sufficient for the demo; this is the honest live number.
- **Threat model page:** the one-page answer to "what can the attacker actually do?" — write
  telemetry, steal a token, not modify the airlock. Depends on the taint-boundary and slice
  decisions; now writable from C10/C15.
- **Scenario-suite expansion beyond the ten:** new incidents after the ablation is stable.

## Out of scope

<!-- Work ruled beyond this destination. It never graduates. -->

- A real SIEM, log store, or detection-rule engine.
- Offensive tooling against real systems. (The red-team *generator* is fog; attacking real systems is
  not.)
- Kubernetes or cloud **deployment**, and a Kubernetes adapter/stub. The slice ships sim + Docker;
  C11 ruled the stub out. A K8s *stub* was a scope question, now answered no.
- Model training or fine-tuning.
- A mobile or desktop client.
- Multi-tenant SaaS concerns: billing, orgs, RBAC beyond the capability model.
- The full north-star platform — "an authority layer for any agent" beyond the demonstrated slice.
- Production mutation or real infrastructure beyond the local Compose stack.
- Memory capture. The snapshot is logs, process table, connections and hashes; claiming more is the
  one unrecoverable credibility risk.
- Evidence signing and key management. The slice uses hashes + an external anchor; a signature is
  not needed for the claim.
- baro internals, or building a Track 01 software factory. The handoff contract is the boundary.
- EUREKA product work or a Track 02 submission. EUREKA is the fallback, not this map.
- Submission logistics: renaming/flipping the origin repo and submitting the entry. Past the
  destination; tracked separately. [T02](tickets/T02-repo-visibility.md)
